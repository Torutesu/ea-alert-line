# EA危険通知LINE — 設計仕様書

作成日: 2026-07-31

## 1. 目的・背景

FXの自動売買（EA）は、経済指標の発表や要人発言によるファンダメンタルズ由来の急変動で大きな損失を出すことがある。本サービスは、相場が荒れる可能性のあるイベントを**事前に**LINEで通知し、利用者がEAを停止するなどの回避行動を取れるようにする。

- 利用者: 少人数（友人・コミュニティ）への配布。LINE公式アカウントの友だち全員に一斉配信
- 課金・個別ユーザー管理・個別設定は**行わない**（YAGNI）

## 2. 通知の種類（4種）

| # | 種類 | タイミング | 情報源 |
|---|------|-----------|--------|
| A | 経済指標 朝ダイジェスト | 毎朝 9:00 JST に当日分一覧 | gaikaex 経済指標カレンダー |
| B | 経済指標 直前アラート | 高重要度指標の発表 30分前（設定可変） | gaikaex 経済指標カレンダー |
| C | 要人発言 予告 | 発言予定の 2時間前（設定可変） | 「今日のスケジュール」記事（トレーダーズ・ウェブ系） |
| D | 要人発言 速報 | 発言ニュース検知後 即時（事後） | みんかぶFX 要人発言ニュース |

### フィルタ条件（A〜C 共通）
- 対象: 主要通貨（USD / JPY / EUR / GBP、設定で変更可）に関係するイベント
- 重要度: ★★（中）以上。直前アラート（B）は ★★★（高）のみ

### 各ソースの調査済み事実（2026-07 時点）
- gaikaex カレンダー（`https://www.gaikaex.com/gaikaex/mark/calendar/`）: 静的HTML。時刻・国名・重要度（★1〜3）・予想・結果・前回値を表形式で掲載。**経済指標のみで要人発言予定は含まれない**。robots.txt はカレンダー本体（PC版）を許容（`/news/`・`/mark/calender_mob/` は Disallow）
- みんかぶFX statement（`https://fx.minkabu.jp/news?category=statement`）: **事後の発言ニュース速報**。発言者名・時刻・発言要旨の見出し。robots.txt 許容、公式サイトマップ `news.xml` あり
- みんかぶFX indicators（`https://fx.minkabu.jp/indicators`）: 経済指標のみ。gaikaex のバックアップソースとする
- 日本語で「要人発言の予定」を構造化データとして持つソースは存在せず、トレーダーズ・ウェブ「今日のスケジュール」記事（Yahoo!ファイナンス配信あり）の文章から抽出する

## 3. アーキテクチャ

言語: **Python 3.12+**。実行環境: **VPS（常時稼働）＋ cron**。

```
[Fetchers 取得層]   ソース別モジュール: 指標カレンダー / 発言予定記事 / 発言速報
        ↓ 共通イベントモデル（Event）へ正規化
[Filter 絞り込み]   通貨・重要度フィルタ
        ↓
[Store 状態保存]    SQLite: events / sent_log / seen_news
        ↑↓
[Jobs ジョブ層]     cron から起動される日次・5分毎スクリプト
        ↓
[Notifier 通知層]   LINE Messaging API broadcast（日本語テンプレ整形）
```

### 設計方針
- **常駐プロセスは持たない**。cron が各ジョブスクリプトを起動し、状態は SQLite に置く。プロセスが死んでも次の cron 実行で自動復帰する
- 各層は単一責務・疎結合とし、パーサ・時刻判定・通知整形を個別にユニットテスト可能にする

### 共通イベントモデル（Event）
| フィールド | 内容 |
|---|---|
| `id` | ソース＋日時＋タイトルから導出する安定キー（重複排除・送信済み判定に使用） |
| `kind` | `indicator`（経済指標）/ `speech`（発言予定）/ `statement`（発言速報） |
| `datetime_jst` | イベント日時（JST） |
| `country` | 国・地域 |
| `title` | イベント名（日本語） |
| `importance` | 1〜3（★の数。速報は3扱い） |
| `forecast` / `previous` | 予想値・前回値（指標のみ、任意） |
| `source_url` | 出典URL |

## 4. ジョブ設計（cron）

| スケジュール | ジョブ | 処理内容 |
|---|---|---|
| 毎日 06:00 | `fetch_daily` | gaikaex カレンダー＋「今日のスケジュール」記事を取得・パースし、当日イベントを SQLite に upsert |
| 毎日 09:00 | `send_digest` | 当日の指標イベント（フィルタ後）を一覧整形して broadcast（種類A） |
| 5分ごと | `tick` | (1) 保存済みイベントのうち「指標30分前」「発言2時間前」の閾値に到達した未送信分を送信（B・C）(2) みんかぶ statement をポーリングし、未見 ID の新着を速報送信（D） |

- **冪等性**: `sent_log`（event_id × 通知種別）で二重送信を防止。5分毎ジョブが遅延・重複起動しても安全
- **閾値判定**: 「発表時刻 − X分 ≤ 現在時刻 < 発表時刻」かつ未送信、で判定（cron の粒度による取りこぼしを防ぐ）

## 5. LINE 通知

- **方式**: LINE Messaging API の `broadcast`（友だち全員へ一斉プッシュ）。LINE Notify は 2025年3月に終了済みのため使用しない
- **前提準備（ユーザー作業）**: LINE Developers で Messaging API チャネルを作成し、チャネルアクセストークン（長期）を取得。利用者は公式アカウントを友だち追加
- **無料枠**: 月200通まで無料。少人数×1日数通で収まる想定だが、超過リスクは通知種別の設定 on/off で調整可能とする

### メッセージテンプレート例
- A: `☀️ 今日の経済指標 7/31（木）\n21:30 🇺🇸 米PCEデフレーター ★★★（予想 2.3% / 前回 2.4%）\n23:00 🇺🇸 ミシガン大消費者信頼感 ★★`
- B: `⚠️ まもなく発表（30分後）\n21:30 🇺🇸 米PCEデフレーター ★★★`
- C: `🗣️ 2時間後に要人発言\n23:00 パウエルFRB議長 発言予定`
- D: `🚨【速報】要人発言\nベイリー英中銀総裁「CPIは予想を下回り心強い」\n▶ <出典URL>`

### 著作権・規約配慮
- 速報（D）は**見出し＋出典リンクのみ**。記事本文の転載はしない
- 各ソースへのアクセスは日次1回＋5分毎ポーリング程度に抑え、User-Agent を明示する

## 6. エラー処理・堅牢性

| 事象 | 対応 |
|---|---|
| スクレイプ HTTP 失敗 | リトライ（指数バックオフ 3回）。失敗継続時は前回取得キャッシュで運用 |
| パース結果 0 件 | サイト構造変更の疑いとして**管理者向け警告を LINE 送信**（利用者向けとはメッセージを区別） |
| 発言予定の抽出漏れ | 文章パースゆえ漏れは許容し、速報（D）を最終防衛ラインとする |
| LINE API 失敗 | リトライ。失敗はログに記録 |
| VPS/cron 停止 | cron ベースなので再起動後に自動復帰。`sent_log` により過去分の重複送信なし |

## 7. 設定（config.yaml）

- 対象通貨リスト（デフォルト: USD, JPY, EUR, GBP）
- 重要度閾値（ダイジェスト/直前アラート個別）
- 直前アラートの分数（デフォルト 30分）、発言予告の分数（デフォルト 120分）
- 通知種別ごとの on/off（A〜D 個別）
- LINE チャネルアクセストークン（環境変数参照）
- 管理者通知先（LINE userId）

## 8. テスト方針

- 各パーサ: 実サイトの HTML を保存した固定フィクスチャに対するユニットテスト（構造変更検知テストを兼ねる）
- 閾値判定ロジック: 時刻を注入可能にし、境界値（ちょうど30分前・跨ぎ・重複起動）をテスト
- Notifier: LINE API をモック化し、テンプレート整形を検証
- 結合: SQLite を一時ファイルで作り、fetch → tick → 送信記録の一連をテスト

## 9. スコープ外（YAGNI）

- ユーザーごとの個別設定・課金・解約管理
- Web 管理画面
- 英語ソース（Forex Factory 等）の併用・翻訳レイヤー
- 指標の「結果値」の事後通知（将来検討）
